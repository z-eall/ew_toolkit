Sometimes `prefab:` + `type:` matches more than you want — every Boar, say, not just the tough ones. `filter:` narrows it down to only the objects that match a condition:

```yaml
- prefab: Boar
  type: create
  filter: int, level, 2;3  # only 1-star or 2-star — a semicolon marks a range (level 2 through 3)
  data: strongBoar
```

<Aside type="caution">
Don't do this: `filter:`'s value is already split as `type, key, value` — a comma there doesn't add a second number to check, it gets read as part of the value text itself. To check a range, use a semicolon (`2;3`).
</Aside>

```yaml
# WRONG — the comma gets folded into the value as the text "2,3", which isn't a number;
# the level check is then silently skipped, so this matches every Boar, not just 1-2 star ones
- prefab: Boar
  type: create
  filter: int, level, 2,3
  data: strongBoar
```

```yaml
# CORRECT — semicolon marks the range
- prefab: Boar
  type: create
  filter: int, level, 2;3
  data: strongBoar
```

Same three pieces as a field edit (see [Understanding Fields](/ew_toolkit/ew_wiki/ewp/concepts/basic-fields/)) — `type, field, value` — just checking a value instead of setting one. `bannedFilter:` does the opposite: matches everything *except* that condition:

```yaml
- prefab: Boar
  type: create
  bannedFilter: int, level, 1  # skip the plain, un-starred ones
  data: strongBoar
```

<Aside type="tip">
`filter:` and `bannedFilter:` also accept a saved data entry's name instead of spelling out a field, e.g. `filter: strongBoar` — matches whenever the object already has that entry applied.
</Aside>

<Aside type="tip">
`filter:`/`bannedFilter:` also work inside a nearby-object check, not just on the object itself — see [Filter: by Objects](/ew_toolkit/ew_wiki/ewp/concepts/objects-filtering/).
</Aside>
