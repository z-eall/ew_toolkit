[Understanding Functions](/ew_wiki/ewp/concepts/basic-functions/) introduced Basic, Text, and Numeric functions one at a time. This page's main job is showing them chained — a function's result is just a value, so any function that accepts a value can take another function's output as its own parameter, as deep as the problem needs. That splits into two kinds of chaining: combining *different* categories (Text + Numeric), and chaining Numeric functions with themselves for a math trick EWP has no single function for. Vector gets a quick reference too, since it's a genuinely new category Understanding Functions didn't cover, just a rarely-needed one.

<Aside type="note">
As always, the mod's own [functions.md](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) is the complete, always-current list. This page picks out the ones worth a worked example — not every function in every category.
</Aside>

## Combining functions across categories

### Case study: a Text-and-Numeric combo for a chat-submitted name

Text functions reshape words; Numeric functions do arithmetic — nesting one inside the other answers questions neither could alone, like "how much of a length budget is left":

```yaml
- prefab: Player
  type: say, namebase *
  command: s Base name registered as <upper_<par_1>> — <max_0_<sub_20_<len_<par_1>>>> character(s) left before the 20-limit.
```

`<len_<par_1>>` (Text) measures what the player typed; `<sub_20_X>` (Numeric) subtracts that from a 20-character budget; `<max_0_X>` clamps it so a name that's already over budget reports `0` left, not a negative number — the same clamp-a-countdown shape used on the [type: time page](/ew_wiki/ewp/concepts/advanced-triggers-time/#case-study---counting-down-to-a-fixed-day). `<upper_<par_1>>` (also Text) just formats the name for display; nothing here actually enforces the limit — EWP has no function that trims a string, so this reports the budget, it doesn't cut anyone off.

## Chaining Numeric functions

Every example below stays inside one category — Numeric functions fed into other Numeric functions — to do something no single function manages alone.

### Case study: rounding to a fixed number of decimal places

`<round_X>` only ever returns a whole number — there's no built-in "round to 2 decimal places." Shifting the decimal point out of the way first, rounding, then shifting it back gets the same result:

```yaml
- prefab: Player
  type: say, piapprox
  command: s <mul_0.01_<round_<mul_100_<div_22_7>>>>
```

`<div_22_7>` is `3.142857...`; `<mul_100_X>` shifts it to `314.2857...` so `<round_X>` has two digits worth keeping when it rounds to the nearest whole number (`314`); `<mul_0.01_X>` shifts it back down to `3.14`. Multiply by `1000`/`0.001` instead of `100`/`0.01` for 3 decimal places, and so on.

### Case study: a weighted roll

Adding two random rolls together weights the result toward the middle of the range, instead of an even spread — the same reason two dice most often sum to 7:

```yaml
- prefab: Player
  type: say, rolldamage
  command: s You deal <add_<randi_1_7>_<randi_1_7>> damage
  # two small rolls summed, weighted toward the middle instead of one flat roll
```

`<randi_1_7>` (Numeric) rolls a random whole number from 1 up to, but not including, 7 — twice, independently — and `<add_X_Y>` sums them. A single `<randi_1_13>` would spread evenly across the same 2-12 range; summing two smaller rolls instead makes the middle of that range far more likely than either end.

### Case study: advantage and disadvantage rolls

`<max_X_Y>`/`<min_X_Y>` don't just pick between two known numbers — feeding them two separate dice rolls gives the classic D&D "advantage" (roll twice, keep the better) and "disadvantage" (roll twice, keep the worse) mechanic, no extra data or filters needed:

```yaml
- prefab: Player
  type: say, attack
  command: s Advantage roll: <max_<randi_1_21>_<randi_1_21>>
  # disadvantage would swap <max_ for <min_
```

Two independent `<randi_1_21>` rolls (1-20, a d20's usual range); `<max_X_Y>` keeps the higher for advantage, `<min_X_Y>` the lower for disadvantage — the same two functions [Understanding Functions](/ew_wiki/ewp/concepts/basic-functions/#kinds-of-functions) already introduced, just fed two random rolls instead of two fixed numbers.

### Case study: distance without the Vector category

[Vector functions](#vector-functions) below have a ready-made `<distance_A_B>` for 3D positions — but the same idea (Pythagoras: distance² = X² + Y²) works with plain Numeric functions too, useful any time the two numbers aren't already packaged as a vector:

```yaml
- prefab: Player
  type: say, !triangle * *
  command: s That's <sqrt_<add_<pow_<par_1>_2>_<pow_<par_2>_2>>>m away.
```

Saying `!triangle 5 10` (5 meters right, 10 forward) reports `11.18m`: `<pow_X_2>` squares each leg, `<add_A_B>` sums the squares, `<sqrt_X>` finishes the formula.

## Custom data (global)

`<save_X_Y>`/`<load_X>`/`<clear_X>` are a **second, separate storage mechanism** from the per-object `data:` covered on [Custom Data: Your Own Flags](/ew_wiki/ewp/concepts/custom-data/) — one shared slot, not attached to any object, most players call it an **EWP key**. ## Vector functions

<Aside type="note">
Used less often than the categories above — kept brief here as a quick reference, not a full walkthrough.
</Aside>

A **vector** here means a 3D position or direction — the same `x,z,y` order `<pos>` already returns. Vector functions do arithmetic on two or three of those at once instead of one number at a time:

- `<distance_A_B>` — straight-line distance between vectors A and B.
- `<lerp_A_B_T>` — a point interpolated between A and B, at factor T (`0` is A, `1` is B, `0.5` is the midpoint).
- `<normalize_V>`, `<magnitude_V>` — a vector shrunk to length 1, or its own length.
- `<vecx_V>`, `<vecy_V>`, `<vecz_V>` — pull a single axis back out of a vector.

...and others — `<dot_A_B>`, `<cross_A_B>`, `<angle_A_B>`, `<project_V_N>`, `<reflect_D_N>` cover the rest of the 3D-math toolbox.

<Aside type="note">
`<add_A_B>`, `<sub_A_B>`, `<mul_A_B>`, and `<div_A_B>` exist in *both* Vector and [Numeric](/ew_wiki/ewp/concepts/basic-functions/#kinds-of-functions) under the exact same names — EWP tells them apart by what you hand in, not by which one you meant. Feed `<add_A_B>` two vectors and every matching component adds; feed it a vector and a plain number and the number adds to *every* component. Same name, different behavior depending on the shape of what's passed in.
</Aside>

A worked example — distance to the nearest of two fixed points, useful for something like picking whichever of two portals is closer:

```yaml
- prefab: Player
  type: say, nearestgate
  command: s <min_<distance_<pos>_100,0,50>_<distance_<pos>_-200,0,300>>m to the nearer gate
```

`<pos>` supplies the player's own position; each `<distance_A_B>` measures to one fixed gate coordinate; `<min_X_Y>` (a Numeric function — plain numbers work fine as its input, since distance already returned one) picks the smaller result.
