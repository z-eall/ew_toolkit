[Understanding Functions](/ew_wiki/ewp/concepts/basic-functions/) introduced Basic, Text, and Numeric functions one at a time. This page's main job is showing them **combined** — a function's result is just a value, so any function that accepts a value can take another function's output as its own parameter, chained as deep as the problem needs. Vector and Long numbers get a quick reference too, since they're genuinely new categories Understanding Functions didn't cover, just rarely-needed ones.

<Aside type="note">
As always, the mod's own [functions.md](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) is the complete, always-current list. This page picks out the ones worth a worked example — not every function in every category.
</Aside>

## Combining functions across categories

### Case study: mixing two different clocks in one message

Valheim's in-game clock ([Time functions](/ew_wiki/ewp/concepts/advanced-triggers-time/#time-functions-read-the-clock-this-trigger-reacts-to-it-changing), `<day>`) and the server's real-world clock ([Realtime functions](/ew_wiki/ewp/concepts/advanced-triggers-realtime/#reading-the-result-realtime-and-friends), `<realtime_X>`) are two entirely separate systems, each taught on its own trigger page — but nothing stops a single `command:` from reading both at once:

```yaml
- prefab: Player
  type: say, worldclock
  command: s Day <day>, server time is <realtime_HH:mm>
```

### Case study: a Text-and-Numeric combo for a chat-submitted name

Text functions reshape words; Numeric functions do arithmetic — nesting one inside the other answers questions neither could alone, like "how much of a length budget is left":

```yaml
- prefab: Player
  type: say, namebase *
  command: s Base name registered as <upper_<par_1>> — <max_0_<sub_20_<len_<par_1>>>> character(s) left before the 20-limit.
```

`<len_<par_1>>` (Text) measures what the player typed; `<sub_20_X>` (Numeric) subtracts that from a 20-character budget; `<max_0_X>` clamps it so a name that's already over budget reports `0` left, not a negative number — the same clamp-a-countdown shape used on the [type: time page](/ew_wiki/ewp/concepts/advanced-triggers-time/#case-study---counting-down-to-a-fixed-day). `<upper_<par_1>>` (also Text) just formats the name for display; nothing here actually enforces the limit — EWP has no function that trims a string, so this reports the budget, it doesn't cut anyone off.

### Case study: a Numeric-only weighted roll

Adding two random rolls together weights the result toward the middle of the range, instead of an even spread — the same reason two dice most often sum to 7:

```yaml
- prefab: Player
  type: say, rolldamage
  command: s You deal <add_<randi_1_7>_<randi_1_7>> damage (two small rolls, weighted toward the middle instead of one flat roll)
```

`<randi_1_7>` (Numeric) rolls a random whole number from 1 up to, but not including, 7 — twice, independently — and `<add_X_Y>` sums them. A single `<randi_1_13>` would spread evenly across the same 2-12 range; summing two smaller rolls instead makes the middle of that range far more likely than either end.

## Custom data (global)

`<save_X_Y>`/`<load_X>`/`<clear_X>` are a **second, separate storage mechanism** from the per-object `data:` covered on [Custom Data: Your Own Flags](/ew_wiki/ewp/concepts/custom-data/) — one shared slot, not attached to any object, most players call it an **EWP key**. Full explanation, every function, and worked examples (simple and advanced) live on their own page: [Custom Data: EWP Key](/ew_wiki/ewp/concepts/ewp-key/) — including how an EWP key compares to the older, simpler `globalkey` world flag.

## Vector functions

<Aside type="note">
Used less often than the categories above — kept brief here as a quick reference, not a full walkthrough.
</Aside>

A **vector** here means a 3D position or direction — the same `x,z,y` order `<pos>` already returns. Vector functions do arithmetic on two or three of those at once instead of one number at a time:

- `<distance_A_B>` — straight-line distance between vectors A and B.
- `<lerp_A_B_T>` — a point interpolated between A and B, at factor T (`0` is A, `1` is B, `0.5` is the midpoint).
- `<normalize_V>`, `<magnitude_V>` — a vector shrunk to length 1, or its own length.
- `<vecx_V>`, `<vecy_V>`, `<vecz_V>` — pull a single axis back out of a vector.

...and others — `<dot_A_B>`, `<cross_A_B>`, `<angle_A_B>`, `<project_V_N>`, `<reflect_D_N>` cover the rest of the 3D-math toolbox.

<Aside type="note">
`<add_A_B>`, `<sub_A_B>`, `<mul_A_B>`, and `<div_A_B>` exist in *both* Vector and [Numeric](/ew_wiki/ewp/concepts/basic-functions/#kinds-of-functions) under the exact same names — EWP tells them apart by what you hand in, not by which one you meant. Feed `<add_A_B>` two vectors and every matching component adds; feed it a vector and a plain number and the number adds to *every* component. Same name, different behavior depending on the shape of what's passed in.
</Aside>

A worked example — distance to the nearest of two fixed points, useful for something like picking whichever of two portals is closer:

```yaml
- prefab: Player
  type: say, nearestgate
  command: s <min_<distance_<pos>_100,0,50>_<distance_<pos>_-200,0,300>>m to the nearer gate
```

`<pos>` supplies the player's own position; each `<distance_A_B>` measures to one fixed gate coordinate; `<min_X_Y>` (a Numeric function — plain numbers work fine as its input, since distance already returned one) picks the smaller result.

## Long numbers

<Aside type="note">
Used less often than the category above — kept brief here as a quick reference, not a full walkthrough.
</Aside>

Valheim tracks time internally as ticks — a number far bigger than the ordinary [Numeric functions](/ew_wiki/ewp/concepts/basic-functions/#kinds-of-functions) are built for, per `functions.md`'s own note that these exist "usually only needed when calculating with game ticks." [`<ticks>`](/ew_wiki/ewp/concepts/advanced-triggers-time/#time-functions-read-the-clock-this-trigger-reacts-to-it-changing) returns one of these oversized numbers — arithmetic on it needs the `long` variant of the function, not the regular one:

- `<addlong_X_Y>`, `<sublong_X_Y>`, `<mullong_X_Y>`, `<divlong_X_Y>`, `<modlong_X_Y>` — same jobs as `<add_X_Y>`/`<sub_X_Y>`/`<mul_X_Y>`/`<div_X_Y>`/`<mod_X_Y>`, just returning a long instead of a regular number.
- `<calclong_X>` — evaluates a whole math expression (built from regular functions) and returns the result as a long, for when nesting individual `long` functions gets clunky.

`functions.md` states each second is `10000000` ticks. Working out the tick value 10 seconds from now:

```yaml
- prefab: Player
  type: say, tickcheck
  command: s <addlong_<ticks>_100000000>  # <ticks> now, plus 10 seconds' worth of ticks
```
