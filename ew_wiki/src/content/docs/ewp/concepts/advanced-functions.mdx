This page picks up exactly where [Understanding Functions](/ew_wiki/ewp/concepts/functions/) left off — Vector, Long numbers, Custom data (global), and Time, the four categories it named but didn't teach. Everything here still follows the same `<name_param1_param2>` shape; if that part isn't already familiar, start there first.

<Aside type="note">
As always, the mod's own [functions.md](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) is the complete, always-current list. This page picks out the ones worth a worked example — not every function in every category.
</Aside>

## Vector functions

A **vector** here means a 3D position or direction — the same `x,z,y` order `<pos>` already returns. Vector functions do arithmetic on two or three of those at once instead of one number at a time:

- `<distance_A_B>` — straight-line distance between vectors A and B.
- `<lerp_A_B_T>` — a point interpolated between A and B, at factor T (`0` is A, `1` is B, `0.5` is the midpoint).
- `<normalize_V>`, `<magnitude_V>` — a vector shrunk to length 1, or its own length.
- `<vecx_V>`, `<vecy_V>`, `<vecz_V>` — pull a single axis back out of a vector.

...and others — `<dot_A_B>`, `<cross_A_B>`, `<angle_A_B>`, `<project_V_N>`, `<reflect_D_N>` cover the rest of the 3D-math toolbox.

<Aside type="note">
`<add_A_B>`, `<sub_A_B>`, `<mul_A_B>`, and `<div_A_B>` exist in *both* Vector and [Numeric](/ew_wiki/ewp/concepts/functions/#kinds-of-functions) under the exact same names — EWP tells them apart by what you hand in, not by which one you meant. Feed `<add_A_B>` two vectors and every matching component adds; feed it a vector and a plain number and the number adds to *every* component. Same name, different behavior depending on the shape of what's passed in.
</Aside>

A worked example — distance to the nearest of two fixed points, useful for something like picking whichever of two portals is closer:

```yaml
- prefab: Player
  type: say, nearestgate
  command: s <min_<distance_<pos>_100,0,50>_<distance_<pos>_-200,0,300>>m to the nearer gate
```

`<pos>` supplies the player's own position; each `<distance_A_B>` measures to one fixed gate coordinate; `<min_X_Y>` (a Numeric function — plain numbers work fine as its input, since distance already returned one) picks the smaller result.

## Long numbers

Valheim tracks time internally as ticks — a number far bigger than the ordinary [Numeric functions](/ew_wiki/ewp/concepts/functions/#kinds-of-functions) are built for, per `functions.md`'s own note that these exist "usually only needed when calculating with game ticks." `<ticks>` (covered below, under Time) returns one of these oversized numbers — arithmetic on it needs the `long` variant of the function, not the regular one:

- `<addlong_X_Y>`, `<sublong_X_Y>`, `<mullong_X_Y>`, `<divlong_X_Y>`, `<modlong_X_Y>` — same jobs as `<add_X_Y>`/`<sub_X_Y>`/`<mul_X_Y>`/`<div_X_Y>`/`<mod_X_Y>`, just returning a long instead of a regular number.
- `<calclong_X>` — evaluates a whole math expression (built from regular functions) and returns the result as a long, for when nesting individual `long` functions gets clunky.

`functions.md` states each second is `10000000` ticks. Working out the tick value 10 seconds from now:

```yaml
- prefab: Player
  type: say, tickcheck
  command: s <addlong_<ticks>_100000000>  # <ticks> now, plus 10 seconds' worth of ticks
```

## Custom data (global)

`<save_X_Y>`/`<load_X>`/`<clear_X>` are a **second, separate storage mechanism** from the per-object `data:` covered on [Custom Data: Your Own Flags](/ew_wiki/ewp/concepts/custom-data/) — easy to conflate because both read back with a similarly-named function. The difference:

- Per-object `data:` (`<int_*>`, `<string_*>`, ...) lives *on one object*. Every Boar has its own copy.
- Global custom data (`<save_X_Y>`, `<load_X>`) isn't attached to any object at all — one shared slot, the same value no matter which object's rule reads it.

- `<save_X_Y>` — writes value Y under key X.
- `<load_X=default>` — reads the key back, or the fallback if it was never saved.
- `<clear_X>` — removes the key entirely. Wildcard `*` removes multiple keys at once.
- `<save++_X>` / `<save--_X>` — shorthand for "add/subtract 1", creating the key at `1`/`-1` if it didn't exist yet.

<Aside type="caution">
A wildcard `*` in `<save_*_Y>`'s key only sets keys that **already exist** — it can't create new ones. `<clear_*>`'s wildcard has no such restriction; it deletes whatever matches.
</Aside>

Because `<save_X_Y>`/`<clear_X>` write a value rather than fetch one, they're normally run through `exec:` — a rule-entry field whose only job is to run a function and discard whatever it returns, rather than showing it in a message or storing it in `data:`:

```yaml
- prefab: Player
  type: say, markhome
  exec: <save_homeAnchor_<pos>>  # writes the player's current position to a global slot, shows nothing
  command: s Anchor saved.
```

### Combined example: an anchor point any object can check against

This ties a vector function to a global save/load — genuinely advanced, since it needs both pieces at once. One rule drops an anchor at the player's current position; a second rule, triggered from anywhere, reports distance back to it:

```yaml
- prefab: Player
  type: say, markhome
  exec: <save_homeAnchor_<pos>>
  command: s Anchor saved.

- prefab: Player
  type: say, distancehome
  command: s <distance_<pos>_<load_homeAnchor=0,0,0>>m from your anchor  # 0,0,0 fallback if no anchor was ever saved
```

`<pos>` in the second rule is whichever player says `distancehome` — not necessarily the one who set the anchor. The anchor itself isn't tied to any object, so any player, at any time, can check their distance from it.

## Time functions

<Aside type="note">
This section is about *functions* that read the clock — not the [`type: time`](/ew_wiki/ewp/concepts/advanced-triggers-time/)/[`type: realtime`](/ew_wiki/ewp/concepts/advanced-triggers-realtime/) **triggers** that fire a rule on a schedule. A function here only reads a value; it never causes a rule to run on its own.
</Aside>

- `<day>` — whole days since the world started.
- `<time>` — seconds since the world started (`1800` seconds per in-game day).
- `<ticks>` — the same, in ticks (see Long numbers above).
- `<time_X>` — formats game time using a .NET `DateTime` format string, e.g. `<time_yyyy-MM-dd HH:mm:ss>`.
- `<realtime>` — real-world Unix time in seconds.
- `<realtime_X>` — formatted real-world time, server's own timezone, e.g. `<realtime_HH:mm:ss>`.
- `<realtime_X_Y>` — same, with an explicit timezone offset `Y` instead of the server's own.

```yaml
- prefab: Player
  type: say, worldclock
  command: s Day <day>, server time is <realtime_HH:mm>
```

<Aside type="tip">
Need Eastern time on a server running elsewhere? `<realtime_HH:mm_-5>` applies the offset without touching the server's own clock — see `functions.md`'s own example for the exact syntax.
</Aside>
