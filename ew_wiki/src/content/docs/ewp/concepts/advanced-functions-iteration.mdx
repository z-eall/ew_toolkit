`<iter_...>` and `<iter2_...>` build a range of values and combine them into one, using whichever [Numeric function](/ew_toolkit/ew_wiki/ewp/concepts/basic-functions/) you name as the combiner. They turn "add these five together" into "add however many of these together," so growing the range only means changing a number, not rewriting the whole line.

<Aside type="note">
As always, the mod's own [functions.md](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) is the complete, always-current reference. This page is the worked walkthrough functions.md doesn't have room for.
</Aside>

## `iter` — combine a range of values

```
<iter_OP_MINI_MAXI_TEMPLATE>
```

- **`OP`** — the function that combines the results: `add`, `sub`, `mul`, `div`, `mod`, `min`, `max`, or the `...long` variants (not a complete list — any function built to take several values works here, but these are the ones worth reaching for).
- **`MINI`/`MAXI`** — the range to cover, inclusive.
- **`TEMPLATE`** — a small pattern containing the letter `i`, standing in for the current number on each pass.

### Case study: summing a range of numbers

```yaml
- prefab: Player
  type: say, sumtest
  command: s <iter_add_1_3_i>
```

`<iter_add_1_3_i>` sums 1 through 3: the template `i` becomes `1`, `2`, `3` in turn, and `add` combines them into `1+2+3 = 6`. Written out by hand, that's exactly `<add_1_2_3>` — `iter` builds the same chain from a range instead of a fixed list, so summing 1 through 20 instead is a one-number edit (`3` → `20`), not a much longer line.

<Aside type="note">
A range of exactly one number (`MINI` and `MAXI` the same) skips `OP` entirely and returns that single value plain: `<iter_add_5_5_i>` is `5`, not `add` run on a single input.
</Aside>

### Case study: totaling a numbered set of fields

An object's `ints:`/`floats:` storage is flat key-value, not a list — so a loot table, a quest counter, or any set of numbered slots ends up as separate fields: `val_1`, `val_2`, `val_3`, and so on. A template isn't limited to plain numbers — naming a function pattern instead builds one call per number in the range, so `int_val_i` reads a different field on every pass:

```yaml
- prefab: Container
  type: change, InUse
  command: s Total so far = <iter_add_1_5_int_val_i>
```

`<iter_add_1_5_int_val_i>` reads `val_1` through `val_5` and sums them — the same result as writing `<add_<int_val_1>_<int_val_2>_<int_val_3>_<int_val_4>_<int_val_5>>` by hand, except a sixth slot later only means changing `5` to `6`, not adding a sixth lookup by hand.

## `iter2` — combine a two-dimensional grid

```
<iter2_OP_MINI_MAXI_MINJ_MAXJ_TEMPLATE>
```

`iter2` is `iter` with a second loop variable, `j`, for building a grid of values before combining them. The evaluation order is fixed: **`j` is the outer loop, `i` is the inner loop.** For `MINI=1,MAXI=2,MINJ=1,MAXJ=2`, the four passes run in this order: `(i=1,j=1)`, `(i=2,j=1)`, `(i=1,j=2)`, `(i=2,j=2)`.

For an order-blind `OP` (`add`, `mul`, `min`, `max`), that order never shows up in the final number. It matters for an order-sensitive `OP` (`sub`, `div`, `mod`), or a template building something positional rather than a straight combine.

### Case study: a grid total

```yaml
- prefab: Player
  type: say, gridtotal
  command: s <iter2_add_1_2_1_2_i_mul_j>
```

Each pass multiplies its own `i` and `j` first, then `add` sums all four products: `(1×1)=1`, `(2×1)=2`, `(1×2)=2`, `(2×2)=4` → `1+2+2+4 = 9`. A small grid, reduced to one number, in one line — the real reason to reach for `iter2` over plain `iter`.

<Aside type="caution">
Don't do this: use a two-dimensional range but write a template that only mentions `i`, leaving `j` out.

```yaml
command: s <iter2_add_1_2_1_2_i>
```

All 4 passes still run — nothing about `iter2` requires `j` to appear in the template — so this quietly counts each `i` value twice, once per `j`, and returns `1+2+1+2 = 6`. Nothing flags it as wrong. A 2D total that looks doubled (or tripled, for a 3-wide `j` range) is usually a template that dropped one of its two tokens.
</Aside>
