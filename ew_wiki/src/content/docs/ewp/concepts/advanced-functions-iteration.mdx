`<iter_...>` and `<iter2_...>` build a range of values and combine them into one, using whichever [Numeric function](/ew_toolkit/ew_wiki/ewp/concepts/basic-functions/) you name as the combiner. They turn "add these five together" into "add however many of these together," so growing the range only means changing a number, not rewriting the whole line.

<Aside type="note">
As always, the mod's own [functions.md](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) is the complete, always-current reference. This page is the worked walkthrough functions.md doesn't have room for.
</Aside>

## `iter` — combine a range of values

```
<iter_OP_MINI_MAXI_TEMPLATE>
```

- **`OP`** — the function that combines the results: `add`, `sub`, `mul`, `div`, `mod`, `min`, `max`, or the `...long` variants (not a complete list — any function built to take several values works here, but these are the ones worth reaching for).
- **`MINI`/`MAXI`** — the range to cover, inclusive.
- **`TEMPLATE`** — a small pattern containing the letter `i`, standing in for the current number on each pass.

### Case study: totaling a real inventory row

A Wood Chest's storage is a real grid — 5 columns, 2 rows, 10 slots total. `<amount_x_y>` reads one exact slot, counting from `(0,0)` in the top-left corner.

<IterationExplainer kind="iter" />

Written by hand, this is five separate `<amount_x_y>` lookups added together — a wider chest later is a one-number edit, not a longer line typed from scratch.

<Aside type="note">
A range of exactly one number (`MINI` and `MAXI` the same) skips `OP` entirely and returns that single value plain.
</Aside>

## `iter2` — combine a two-dimensional grid

```
<iter2_OP_MINI_MAXI_MINJ_MAXJ_TEMPLATE>
```

`iter2` is `iter` with a second loop variable, `j`, for building a grid of values before combining them — every combination of `i` and `j`, not matched pairs. The evaluation order is fixed: **`j` is the outer loop, `i` is the inner loop.**

The same chest from above, now read in full — both rows, all 10 slots:

This is what `iter` alone can't do — it only ever has one number changing per pass, not two crossed together.

<Aside type="caution">
Don't do this: use a two-dimensional range but write a template that only mentions `i`, leaving `j` out. All 10 passes still run — nothing about `iter2` requires `j` to appear in the template — so this quietly counts row 0 twice instead of reaching row 1 at all, returning 27+27=54 instead of 40. Try the checkbox above to watch it happen.
</Aside>

### Case study: a total that sizes itself to any chest

The case study above still has `4` and `1` typed into `MAXI`/`MAXJ` — this chest's real dimensions, but fixed in the script regardless of what chest it's actually pointed at. Both bounds are just text `iter2` reads *after* everything nested inside them has already resolved — the same inside-out rule any nested function call follows, applied twice, once per dimension. `<int_Container.m_width>` and `<int_Container.m_height>` — plain reads of the chest's own real fields — each resolve to a literal number first, and only then does `iter2` see them as `MAXI`/`MAXJ`.

<IterationExplainer kind="iter2adv" />

Drop this rule onto any chest — 5×2, 8×4, whatever — and it always sums every slot that chest actually has, with nothing to edit. This is `iter2`'s real ceiling: not just a 2D total, but one that never goes stale as the object it's reading changes shape.
