A **data entry** is a group of changes you save under one name, so you can reuse it instead of typing the same edit over and over.

## Why bother saving it

Say you want a Boar to spawn stronger — a higher level, more max health. You could type that out every single time. Or you could save it once, under a name, and just use that name from then on:

```
spawn_object Boar data=strongBoar
```

<StrongBoarData />

Now `strongBoar` is ready to use anywhere, any time — no retyping.

## What a data entry looks like

A data entry is a `name`, plus one or more lists of changes. Which list a change goes in depends on its kind of value:

- `ints` — whole numbers, like `level`
- `floats` — numbers with decimals, like `max_health`
- `strings` — text, like a name
- `bools` — true/false switches
- (and others — `longs`, `vecs`, `quats`, `hashes`, `items` cover more specific cases as you go further)

```yaml
- name: toughBoar
  ints:
  - level, 5
  floats:
  - max_health, 300
```

Apply the whole bundle at once with `data=toughBoar`, instead of listing each change separately.

## Where data.yaml lives

Your client and your server each keep their own `data.yaml` — they don't share one. See [Preparation](/ew_wiki/ewp/preparation/#getting-data-onto-your-server-the-part-that-trips-people-up) for the exact folders and how to copy an entry from one to the other.
