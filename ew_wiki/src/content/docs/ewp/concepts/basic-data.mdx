A **data entry** is a group of changes you save under one name, so you can reuse it instead of typing the same edit over and over.

## Why bother saving it

Say you want a Boar to spawn stronger — starred, with more max health. You could type that out every single time. Or you could save it once, under a name, and just use that name from then on:

```
spawn_object Boar data=strongBoar
```

<StrongBoarData />

Now `strongBoar` is ready to use anywhere, any time — no retyping.

## What a data entry looks like

A data entry is a `name`, plus one or more lists of changes. Which list a change goes in depends on its kind of value:

- `ints` — whole numbers, like `level`
- `floats` — numbers with decimals, like `max_health`
- `strings` — text, like a name
- `bools` — true/false switches
- (and others — `longs`, `vecs`, `quats`, `hashes`, `items` cover more specific cases as you go further)

```yaml
- name: toughBoar
  ints:
  - level, 5
  floats:
  - max_health, 300
```

Apply the whole bundle at once with `data=toughBoar`, instead of listing each change separately.

## Rebuilt or just repainted? `injectData:`

When a rule's `data:` changes something, EWP sometimes has to **rebuild the whole object** to make the change actually show up — like tearing down a toy and snapping it back together with the new piece already in place. Other times it just **saves the value quietly**, no rebuild — like writing a note and tucking it inside, nothing changes on the outside.

Take a Boar's star level: the star glow only appears when the Boar is rebuilt. Save the new level quietly instead, and the Boar's data says it's starred — but it still *looks* like a plain Boar.

```yaml
- prefab: Boar
  type: create
  data: int, level, 3
  injectData: false   # rebuild the Boar so the star actually shows
```

- `injectData: false` — always rebuild. Use this when the change needs to be visible on the object right away.
- `injectData: true` — never rebuild, just save the value quietly. Fine for changes nobody needs to see.

EWP usually picks the right one for you on its own — you only need to set this by hand when that automatic guess gets it wrong.

## Where data.yaml lives

Your client and your server each keep their own `data.yaml` — they don't share one. See [Preparation](/ew_toolkit/ew_wiki/ewp/preparation/#getting-data-onto-your-server) for the exact folders and how to copy an entry from one to the other.
