# ew_wiki — Trusted Sources

Reference list for source-verifying wiki content, per [AGENTS.md](../AGENTS.md)'s source-verify rule. Every source here is pre-approved — check here before asking for research signoff. Found a source that isn't listed? Get signoff once (hub-wide rule), then add it below so the next guide doesn't re-ask.

Each entry: link/path, tier (**official** — from Jere or Iron Gate/Coffee Stain directly; **community** — forums, wikis, hosting vendors, player-written guides), and what it's good for.

## EWP

- `ewp_validator/src/schema.generated.json` and its `*.test.ts` fixtures (in this repo) — **official**, generated straight from EWP's own schema. Check here first for any key/value/type question — fastest ground truth, no network round-trip.
- [expand_world_prefabs](https://github.com/JereKuusela/valheim-expand_world_prefabs) (GitHub, Jere Kuusela) — **official**, the mod's own C# source and README. Ground truth for valid keys/values/mechanics when `ewp_validator/src/schema.generated.json` doesn't settle it (e.g. `type:`'s real enum — confirmed `create`, not the guessed `spawn`, see ticket 04 round 3).
  - [`docs/scripting.md`](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/scripting.md) inside that same repo — the mod's own prose reference for every top-level rule-entry field, `type:`'s full trigger list with per-type semantics, and the `filter:`/`bannedFilter:`/`filters:`/`filterLimit:` system. Better than reading the C# directly for anything field-shaped; check here before the schema for *meaning*, the schema for *valid values*.
  - [`docs/functions.md`](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/functions.md) inside that same repo — the mod's own complete list of every `<name_param>` function, grouped by its own category headings (Functions, Text, Numeric, Vector, Long numbers, Custom data, Time). The wiki's [Understanding Functions](/ew_wiki/ewp/concepts/functions/) page teaches Basic/Text/Numeric and points here for the exhaustive list and the categories not yet covered.
  - [`docs/RPCs.md`](https://github.com/JereKuusela/valheim-expand_world_prefabs/blob/main/docs/RPCs.md) inside that same repo — the mod's own complete list of every supported `objectRpc:`/`clientRpc:` `name:` value. Note the path: it's under `docs/`, not the repo root — a root-level `RPCs.md` link 404s.
  - The mod's own README states `expand_world/ewp_data.yaml` is "created automatically if custom keys are saved" — the auto-generated runtime file every `<save_X_Y>` write lands in, distinct from the author-written `data.yaml`. Quoted and traced against `DataStorage.cs` in `.scratch/ew_toolkit/research/04-reference-validation-feasibility.md` and `.scratch/validator-round2/research/07-custom-key-source-verification.md`. Used on `ewp-key.mdx`.
  - `ExpandWorldPrefabs/PrefabManager.cs` (lines 105-160) and `ExpandWorldPrefabs/PrefabData.cs` (the `TriggerRules`/`InjectData` fields) inside that same repo — read directly when `scripting.md`'s prose ran out: `scripting.md` only says `triggerRules` covers "spawns or remove", but the C# shows a `data:` write is *also* gated by it (`HandleChanged.IgnoreZdo` is set right before the write and cleared right after, suppressing that write's own `type: change` trigger unless `triggerRules: true`). Also confirmed `injectData:`'s respawn-vs-inject-in-place switch (`var inject = info.InjectData ?? data?.CanBeInjected ?? false`). Used on `advanced-triggers-change.mdx` and `basic-data.mdx`.
- `docs/guide-source/1-theory-fundamental/EWP_How_To_Use_Data.md` (local file, DhakhaR) — **community**, original author guide. Source for v1's client-side `BepInEx\config` paths, `infinity_tools.yaml`/`data.yaml` behavior. Re-check anything from here against a live/current source before reuse — written before this correction pass caught errors in how it was applied.
- `docs/guide-source/3-advanced-use-cases/EWP_Maths_Guide.md` (local file, DhakhaR's "Maths with EWP" — Valheim World Editing Discord, #guides) — **community**, not yet ported as its own guide. Source for number-function patterns (weighted random via summed rolls, advantage/disadvantage via `<max_>`/`<min_>`, decimal-place rounding, toggle-via-`<abs_<sub_`) used as inspiration (not excerpted) on `advanced-functions.mdx` and `ewp-key.mdx`.
- [expand_world_events](https://github.com/JereKuusela/valheim-expand_world_events) (GitHub, Jere Kuusela) — **official**, a separate mod by the same author that lets a scripter define entirely new random events (own ids) in `expand_events.yaml`. Source for the "`type: event` also fires on custom, author-defined event ids, not only vanilla ones" claim on the no-prefab-triggers page.
- `docs/guide-source/4-script-examples/3-ewp-advanced/` (local files, maintainer's own live server) — **community**, the maintainer's real, running village-progression scripts (`data_BFV_systemGeneral_VillageStation.yaml`/`expand_prefabs_..._VillageStation.yaml` and their `VillageCargo` counterparts). Source for [Auto-upgrade Stations](/ew_wiki/ewp/examples/auto-upgrade-station/) and [Village Cargo Mission](/ew_wiki/ewp/examples/village-cargo/) — the full six-tier station/feast table, the 15-village/11-destination name lists, and the `MarketPlaceNPC`/`cargomaster` interaction (flagged unconfirmed on that page, since the prefab isn't in Jotunn's list). `data_..._WorldBosses.yaml`/`expand_prefabs_..._WorldBosses.yaml` from the same folder is the source for [World Boss Progression](/ew_wiki/ewp/examples/world-progression/).

## Valheim game data (components, fields, prefabs)

- [Jotunn data dumps](https://valheim-modding.github.io/Jotunn/data/intro.html) (Jotunn modding library docs) — **community** (auto-generated from the live game, not Jere's own docs). Prefab list confirms which components a prefab has (e.g. `portal_wood` → `Piece`/`WearNTear`/`TeleportWorld`); does **not** dump individual field names per component. The [full prefab list](https://valheim-modding.github.io/Jotunn/data/prefabs/prefab-list.html) is the ground truth for whether a prefab ID is real at all — caught `RareTrophy` and `BossBoar` as invented (real prefab is `TrophyNeck`; no "boss boar" creature exists) in ticket 09 round 4.
- [valheimtools.stream/wiki/components](https://valheimtools.stream/wiki/components) — **community** (per-component field dumps, decompiled). Cross-check reference only per hub-wide `AGENTS.md` (never a dependency) — used here only to verify field names already claimed elsewhere, e.g. confirmed `TeleportWorld.m_allowAllItems` real, and caught `activationDistance` as wrong (the real field is `m_activationRange`). Also confirmed `Feast`'s real fields are `m_eatStacks`/`m_useDistance`/`m_foodItem` — caught an invented `Value` field on the `type: change` page, replaced with `eatStacks`.
- [valheim.wiki](https://valheim.wiki/) (redirects to [valheim.weirdgloop.org](https://valheim.weirdgloop.org/)) — **community**, fan-maintained (the site says so itself: "maintained by fans of Valheim... anyone may contribute"). Each creature/item page's Details box lists its real `Internal ID` — useful for a quick single-prefab sanity check; the Jotunn full list above is still the source for an exhaustive or ambiguous lookup.
- [valheimcheats.com/event](https://valheimcheats.com/event) — **community**, console-command reference site. Source for vanilla Valheim's fixed list of random-event ids (`army_eikthyr`, `foresttrolls`, etc.) used with the `event` console command and, per EWP's own docs, `type: event`'s parameter. Cross-checked against community search results (screenrant.com/gamerant.com write-ups) before use — caught `raid_of_the_hour` as an invented event id on the no-prefab-triggers page, replaced with real vanilla ids.

## Valheim / hosting / BepInEx

- [Dedicated servers – Valheim Wiki (Fandom)](https://valheim.fandom.com/wiki/Dedicated_servers) — **community** (fan wiki, documents Iron Gate's official SteamCMD install steps). Used for: dedicated-server app id (`896660`), default install path shape.
- [Developer console – Valheim Wiki (Fandom)](https://valheim.fandom.com/wiki/Developer_console) — **community** (fan wiki). Admin-commands table confirms vanilla console command syntax not documented by any EWP/WEC source, since `setkey`/`removekey`/`resetkeys` are base-game commands, not mod-added ones: `setkey [name]` (adds a global key, no value), `removekey [name]` (removes one, no value), `resetkeys [name]` (removes *all* global keys — the `[name]` parameter is listed as doing nothing). Cross-confirmed at the code level by `valheim-dev`/ServerDevcommands below — `DisableGlobalKeys.cs` Harmony-patches the actual vanilla method `ZoneSystem.RPC_SetGlobalKey(string name)`, name only, no value parameter. Caught `removekey EnemyDamage 95` (an invalid trailing value) on the `type: realtime` page's weekday-buff example.
- [BepInEx dedicated-server discussion #1194](https://github.com/BepInEx/BepInEx/discussions/1194) — **community** (GitHub discussion, not BepInEx's own docs). Used for: `BepInEx\config` sitting beside `valheim_server.exe`/`valheim_server.x86_64`.
- [How to Add/Install Mods to a Valheim Server – XGamingServer](https://xgamingserver.com/blog/how-to-add-install-mods-to-a-dedicated-valheim-server/) — **community** (hosting vendor blog). Used for: general dedicated-server BepInEx folder placement.

## Community-observed, no single source

Facts with wide community agreement but no citable official doc. Mark these clearly in the page itself (e.g. an `<Aside type="note">`) — never present as if sourced.

- `BepInEx\config\expand_world` is EWP's own auto-generated, conventional script folder — EWP scans every subfolder under `config`, but this is the one it creates and uses itself. Maintainer-confirmed, no doc link. Used in: Preparation page's "Getting a script onto your server."
- Load order matters between data and scripts: a script referencing a data entry that isn't loaded yet errors; unused/unloaded data alone does not. Resaving a script's `.yaml` after new data loads makes EWP re-check it against that data. Maintainer-confirmed from direct experience, no doc link. Used in: Preparation page's "Rule of thumb: load data before scripts."
