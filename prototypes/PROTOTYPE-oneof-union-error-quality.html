Discriminator-less array — is a naive oneOf union's error output usable?

The question this prototype answers: EWP script files are one YAML array mixing four entry shapes with no tag field — an EWP rule entry, a WEC data entry, a Value entry, and a Value group. The Schema has to describe this as a oneOf union of four object shapes. JSON Schema validators are historically bad at reporting errors for oneOf unions — a malformed entry can get reported against every branch it didn't match, instead of the one branch it was clearly attempting.

This page runs the same broken YAML through two approaches side by side:

A — Naive oneOf: validate each array item against the full four-branch oneOf schema and show whatever Ajv (a standard JSON Schema validator) reports.

B — Structural pre-check: guess which of the four shapes an item is clearly attempting (by which distinguishing keys are present — valueGroup, value, or name+typed-lists-without-prefab/type → WEC data entry, else → EWP rule entry), then validate against only that one schema.

Use the tabs below to step through scenarios, or edit the YAML directly and click Validate.

How to read this: open this file directly in a browser (double-click, needs internet access for the two CDN scripts). Step through the "Broken" tabs and compare panel A vs panel B. If A's raw Ajv output on the typo'd-key and matches-nothing scenarios reads as noisy/unhelpful compared to B's single clear "guessed branch + its own errors" message, that confirms the ticket's suspicion and the real implementation should use the structural pre-check (B), not a naive oneOf (A), for its actual validation + error-reporting path.
